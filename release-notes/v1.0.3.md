## Multron Download Manager v1.0.3

The Firefox add-on is now on [Mozilla Add-ons](https://addons.mozilla.org/firefox/addon/multron-download-manager/), so it stays installed after Firefox restarts.

### Changes

- **Single files from inside an archive.** In the new download window, **Browse archive contents** lists what is inside a ZIP (also `.jar`, `.apk`, `.docx`, `.epub`), ISO, UDF, TAR, 7z or RAR file on the server, by reading only the archive's index. Tick the files you want and only those are downloaded, each as its own download, optionally with their folders. This needs a server that allows partial downloads. Files that cannot be taken out alone (encrypted, compressed RAR, solid 7z blocks, `.tar.gz` and similar) are marked, and the whole archive can still be downloaded as usual.
- **Firefox add-on from Mozilla Add-ons.** In the extension setup assistant, the Firefox button now opens the add-on's page on Mozilla Add-ons in the browser you picked. Click **Add to Firefox**, then **Add**, and press **Allow** in Multron Download Manager. The add-on is signed by Mozilla, stays installed after a restart and updates by itself. This works for Firefox and its forks (Developer Edition, Nightly, LibreWolf, Waterfox, Floorp, Zen, Mullvad Browser), also as Flatpak. The second option, **Or install the signed .xpi file**, downloads the Mozilla-signed add-on, checks it and opens it in Firefox, so it is permanent as well. A temporary add-on from the extension folder is only offered when that download fails.
- **Signed `.xpi` in the release.** The release now has `multron-browser-extension-firefox-v<version>.xpi`, the same file Mozilla signed for Mozilla Add-ons. Open it in Firefox (or drag it into the window) to install it permanently by hand.
- **“Start this program?” in its own window.** Opening a downloaded program from the download window or a notification closes the download window and asks in a small window of its own, instead of bringing up the main window.
- **Choose files from feed items.** In RSS feeds (also the built-in ones and Internet Archive), each item has a **Choose files** button next to **Download**. It opens the item in the new download window, where you tick only the files you want from the torrent or the archive instead of downloading everything.
- **Security levels cover more.** Picking a level in *Settings → Security* now also sets the protections in other sections. Every level keeps app and yt-dlp updates, checksum checks from the download page and Multron Cloud threat blocking, quarantine and re-checks on. Standard and up ask before a download from the browser starts, High and up remove saved browser cookies when the app closes, and Strict no longer unpacks archives automatically.
- **Installer built with Inno Setup 7.** The Windows installer is now made with Inno Setup 7.1.1, the current version. Installing and updating work as before.
- **Tidier toolbar.** The Discord and Patreon buttons moved out of the main toolbar; they are still in *Settings → Updates & About*.

### Fixes

- **Internet Archive torrents download.** Torrents from archive.org (for example from its RSS feed) have almost no peers and get their data from web seeds, which the torrent engine cannot use, so they stayed at 0 %. A torrent that runs for a minute without any peer or data now switches to its web seeds: each of its files (or the ones you picked) becomes a normal multi-connection download into the same folder.
- **macOS: no more “damaged” app after updating or reinstalling.** The app is now properly (ad-hoc) signed. After an update, the updater clears the download marks from the new app and, if its signature does not check out, signs it again on your Mac, so it opens right away. Multron also no longer puts the quarantine flag on its own release files, so a copy downloaded with Multron opens like an update does. Because the app is not notarized by Apple, the first start of a copy downloaded with a browser still needs **System Settings → Privacy & Security → Open Anyway** once.
- **No false “Disguised program” warning.** Programs with a version number in their name, such as `VSCodiumSetup-x64-1.143.17232.exe`, were marked as disguised because the number before `.exe` looked like a second extension. Now only real decoy extensions count, like `invoice.pdf.exe` or `photo.jpg.scr`.
- **Readable text in the light theme.** The selected browser in the extension setup assistant, the highlighted entry in the command palette, the active filter chips in the link grabber and the selected feed in RSS showed white text on a light background. They now use the theme's text color. The red security alert banners keep white text in both themes.
